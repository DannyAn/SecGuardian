# Trust Boundary Analysis — 信任边界分析参考

> 识别系统中的信任边界，检查跨边界数据传输和操作是否有足够的访问控制。

## 何时使用

适用于涉及用户隔离和权限边界的审计域：
- Authorization — 检查权限边界，防止越权
- Authentication — 检查会话边界，防止会话劫持
- Data Protection — 检查数据访问边界，防止跨租户数据访问
- Secure Transport — 检查网络信任边界

## 典型信任边界

| 边界类型 | 示例 | 风险 |
|----------|------|------|
| 用户边界 | User A ↔ User B | IDOR、越权访问 |
| 角色边界 | 普通用户 ↔ 管理员 | 权限提升 |
| 网络边界 | 公网 ↔ 内网 | 未授权访问 |
| 服务边界 | 服务 A ↔ 服务 B | 服务间未认证调用 |
| 数据边界 | 租户 A ↔ 租户 B | 跨租户数据泄露 |
| 会话边界 | 匿名 ↔ 已认证 | 未认证访问 |

## 跨边界控制检查

对每个信任边界，检查以下控制：

### 认证控制
- 边界入口是否有认证机制？
- 会话管理是否安全？
- Token 是否有有效期限和范围？

### 授权控制
- 是否验证用户身份后才允许跨边界？
- 是否有基于角色的访问控制（RBAC）？
- 是否有基于属性的访问控制（ABAC）？
- 是否检查资源所有权（防止 IDOR）？

### 数据控制
- 跨边界传输的数据是否加密？
- 是否限制了返回给用户的数据范围？
- 是否进行了数据脱敏？

### 审计控制
- 跨边界操作是否记录日志？
- 是否有异常跨边界访问告警？

## 执行步骤

1. 识别系统的信任边界（基于架构分析）
2. 对每条边界，枚举跨越该边界的所有数据流
3. 检查每个跨边界操作的安全控制
4. 验证"最小权限原则"是否实施
5. 标记跨边界控制缺失的风险
