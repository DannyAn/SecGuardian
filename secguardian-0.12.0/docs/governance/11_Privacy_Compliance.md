# 11 — 隐私与合规 (Privacy & Compliance)

> **对应 Sheet:** `11_Privacy_Compliance`
> **牵引方向:** SecGuardian 隐私合规检测能力——覆盖 PII 识别、数据留存、用户同意和跨境数据传输。

---

## 1. 概述

隐私与数据合规是企业和法律的要求。本 sheet 涵盖 **4 大隐私合规分类**，每类 20 条要求，共计 **80 条控制项**。

---

## 2. 分类体系

| 分类 | 控制目标 | 严重度分布 | 主要法规 |
|---|---|---|---|
| **PII** (个人身份信息) | 识别、分类和保护 PII 数据 | 8×Medium, 8×High, 4×Critical | GDPR / PIPL / CCPA |
| **Retention** (数据留存) | 数据保存期限管理 | 6×Medium, 8×High, 6×Critical | GDPR Art.5 / 17 |
| **Consent** (用户同意) | 用户同意管理 | 4×Medium, 6×High, 10×Critical | GDPR Art.7 / ePrivacy |
| **Cross-border** (跨境传输) | 跨法域数据传输合规 | 6×Medium, 6×High, 8×Critical | GDPR Art.44-49 / 中国《个人信息出境安全评估办法》 |

---

## 3. 分类详解与最佳实践

### 3.1 PII 识别与保护

**PII 数据分类示例：**

| 类别 | 示例 | 敏感度 |
|---|---|---|
| 基本身份 | 姓名、电话号码、邮箱 | 中 |
| 生物信息 | 指纹、面部识别、虹膜 | 高 |
| 财务信息 | 银行账号、信用卡号 | 高 |
| 健康信息 | 病历、基因数据 | 高 |
| 位置信息 | GPS 轨迹、常去地址 | 中 |
| 在线行为 | Cookie、浏览历史 | 低 |
| 特殊类别 (GDPR Art.9) | 种族、政治观点、宗教 | 极高 |

**PII 检测规则：**

| 控制项 | 要求 | 严重度 | 检测方式 |
|---|---|---|---|
| PII-01 | 代码库中不硬编码 PII | Critical | 正则匹配 (身份证/手机号模式) |
| PII-02 | API 响应字段标注 PII 标签 | High | Schema 标注检查 |
| PII-03 | 日志中禁止记录原始 PII | High | 日志脱敏检测 |
| PII-04 | 数据库 PII 字段加密 | High | Schema 字段加密标志检查 |
| PII-05 | PII 数据最小化收集 | Medium | 数据收集清单审查 |

### 3.2 数据留存 (Retention)

**GDPR 数据留存原则 (Art.5(1)(e))：**

- 数据保留时间不得超过处理目的所需的时间
- 删除或匿名化过期数据

| 控制项 | 要求 | 严重度 |
|---|---|---|
| RET-01 | PII 数据设置明确保留期限 | High |
| RET-02 | 定期自动清理过期数据 | High |
| RET-03 | 删除机制可验证、可审计 | Critical |
| RET-04 | 数据归档时确保不可恢复删除 | Critical |
| RET-05 | 留存策略文档化并审批 | Medium |
| RET-06 | 用户请求删除后的处理 ≤ 30 天 | High |

**常见数据类型保留期限建议：**

| 数据类型 | 建议期限 | 法律依据 |
|---|---|---|
| 用户账号信息 | 账号关闭后 30 天 | GDPR Art.17 |
| 交易记录 | 7 年 | 税法要求 |
| 审计日志 | 1 年 | PCI DSS |
| PII 处理日志 | 3 年 | GDPR Art.30 |
| Cookie 标识 | ≤ 13 个月 | ePrivacy |

### 3.3 用户同意 (Consent)

**GDPR 对于同意的要求 (Art.4(11), Art.7)：**

1. **自由给予** — 不可捆绑，不可强制性
2. **具体明确** — 分场景、分目的的独立同意
3. **知情** — 必须以清晰、易懂的语言说明用途
4. **明确** — 必须是主动的 affirmative action (非预选勾选)
5. **可撤回** — 撤回必须跟给予同样容易

| 控制项 | 要求 | 严重度 |
|---|---|---|
| CST-01 | 用户首次访问获取明确同意 | Critical |
| CST-02 | 同意记录完整存储与审计 | Critical |
| CST-03 | 用户可随时撤回同意 | Critical |
| CST-04 | 同意粒度——每个处理目的独立 | High |
| CST-05 | 撤回后立即停止数据处理 | High |
| CST-06 | 明确告知第三方数据处理 | Medium |
| CST-07 | Cookie 面板分层次（必要/功能/营销） | Medium |
| CST-08 | 儿童数据处理需监护人同意 | Critical |

### 3.4 跨境数据传输 (Cross-border Transfer)

**中国《个人信息保护法》(PIPL) 第 38-43 条：**

| 要求 | 说明 | 适用方 |
|---|---|---|
| 个人信息保护认证 | 通过具有权限机构的认证 | 所有跨境处理方 |
| 标准合同条款 | 与境外接收方签订标准合同 | 中小企业常见路径 |
| 安全评估 | 向网信办申报 | CIIO 或者处理 100 万人以上 PII |
| 个人信息保护影响评估 (PIA) | 事前评估跨境风险 | 必要前置条件 |

**GDPR 跨境数据传输：**

| 机制 | 说明 |
|---|---|
| **充分性决定** | 欧盟委员会认定目的地国家保护标准充分 (如日本、韩国、英国) |
| **SCC (标准合同条款)** | 2021 年新版，模块化设计 |
| **BCR (有约束力的公司规则)** | 跨国公司内部 |
| **第 49 条例外** | 特定情况 (如用户明确同意、合同履行必要) |

**跨境数据合规检查清单：**

| 控制项 | 要求 | 严重度 |
|---|---|---|
| CB-01 | 数据是否流向已评估的目的地 | Critical |
| CB-02 | 跨境数据传输协议是否签署 | Critical |
| CB-03 | 传输数据清单维护 | High |
| CB-04 | 第三方处理方审计 | Medium |
| CB-05 | PIA 评估完成（跨境场景） | Critical |

## 5. SecGuardian 牵引方向

### 5.1 隐私检测能力

| 阶段 | 能力 | 优先集成 |
|---|---|---|
| **Phase 1** | PII 数据检测 (正则/ML) | 代码库扫描 + 配置文件扫描 |
