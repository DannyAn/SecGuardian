# Project Background

SecGuardian started as an AI-native security assistant for AI coding agents.

The long-term vision is NOT to become another SAST scanner.

The long-term vision is:

    AI Security Engineer

that accompanies the entire software development lifecycle.

Current users:

- AI Coding Agents (Claude Code / OpenCode / Gemini CLI)
- Developers
- Security Engineers

Future users:

- CI/CD
- Security Governance
- Enterprise Security Teams

The current implementation already supports:

- secguard
- secreview
- secfix
- secaudit

These commands must remain unchanged.

------------------------------------------------------------

# Current Problems

The project has gradually evolved.

As a result, several concepts are currently mixed together.

Examples:

- AI workflow
- security workflow
- execution pipeline
- CI/CD pipeline
- governance
- rule execution
- report generation

They work.

But the architecture does not clearly express their responsibilities.

The goal is NOT to rewrite them.

The goal is to make the architecture reflect the product vision.

# Core Design Principles

These principles are now considered architecture decisions.

Do NOT violate them.

------------------------------------------------------------

Architecture Rule 0

SecGuardian models security roles,
not security tools.

Every major module should correspond to
a real-world security responsibility.

Examples:

secguard
→ Secure Coding Advisor

secreview
→ Security Reviewer

secfix
→ Security Remediation Engineer

secaudit
→ Release Security Auditor

Future modules should continue following
real security roles instead of technical tools.

Principle 1

SecGuardian is NOT an AI model.

It is NOT tied to Claude.

It is NOT tied to Gemini.

It is NOT tied to OpenCode.

LLMs are replaceable.

------------------------------------------------------------

Principle 2

Security knowledge is the product.

Prompt is not the product.

Model is not the product.

Knowledge/
Rule Packs/
Protocols/

are the core assets.

------------------------------------------------------------

Principle 3

AI Agents are only runtimes.

Today:

Claude Code

Tomorrow:

Any Coding Agent

SecGuardian should behave consistently.

------------------------------------------------------------

Principle 4

CI/CD is NOT the primary runtime.

CI/CD is another runtime.

Its biggest value is telemetry.

Not scanning.

Telemetry.

------------------------------------------------------------

Principle 5

Developer UX remains the first priority.

Never sacrifice AI Agent experience
for CI/CD compatibility.

------------------------------------------------------------

Principle 6

Everything should eventually converge into one Security Engine.

Today's architecture:

Command

↓

Skill

↓

LLM

↓

Finding

Future architecture:

Command

↓

Skill

↓

Security Engine

↓

Rule Pack

↓

Finding

↓

LLM

↓

Explanation

↓

Patch

Do NOT implement the engine.

Just prepare the architecture.
