## Slide 4：核心架构 —— AI/Renderer 分离

```
┌──────────────────────────────────────────────────────────────┐
│              性能重构后的四层架构 (v4.0)                       │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌──────────────────────────────────────────────────────┐    │
│  │  Layer 1: 语义索引器 (Go, tree-sitter)                │    │
│  │  · 符号表 · 调用图 · alloc/free 配对 · 锁图           │    │
│  │  · 5 语言 × 5 平台编译 · ~70ms 解析速度               │    │
│  └────────────────────┬─────────────────────────────────┘    │
│                       │ index.json                          │
│  ┌────────────────────▼─────────────────────────────────┐    │
│  │  Layer 2: AI 分析引擎                                 │    │
│  │  · 语义理解 · 检测器匹配 · 证据提取 · CVSS 评分       │    │
│  │  · ★ 仅输出结构化 findings.json（非报告文本）          │    │
│  │  · Token 消耗降低 66%（16K→5.5K）                      │    │
│  └────────────────────┬─────────────────────────────────┘    │
│                       │ findings.json                       │
│  ┌────────────────────▼─────────────────────────────────┐    │
│  │  Layer 3: 渲染引擎 (Python, 零依赖)                    │    │
│  │  · 生成 6 种输出文件 · SARIF 2.1.0 · 安全评分计算     │    │
│  │  · 4 段式质量门禁 · CI 退出码 · ~69ms 渲染速度         │    │
│  └────────────────────┬─────────────────────────────────┘    │
│                       │                                     │
│  ┌────────────────────▼─────────────────────────────────┐    │
│  │  Layer 4: 三平台部署 (Claude Code / OpenCode / Gemini)│    │
│  └──────────────────────────────────────────────────────┘    │
│                                                              │
└──────────────────────────────────────────────────────────────┘

演讲者备注：
- 核心设计决策：AI 擅长语义分析但不擅长格式化输出。分离后 token 降 66%
- 渲染器仅 774 行 Python，零依赖，直接放到 CI pipeline 可用
```

## Slide 6：语义索引器 —— 自研 Go 引擎

```
┌──────────────────────────────────────────────────────────────┐
│         secguardian-index — 代码语义索引器                    │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│   技术栈       架构亮点               输出能力                │
│   ┌────────┐  ┌──────────────────┐  ┌──────────────────┐    │
│   │ Go 1.25│  │ 双解析器并行架构   │  │ 符号表 (函数名→   │    │
│   │        │  │ · tree-sitter(cgo)│  │  文件:行号)       │    │
│   │ tree-  │  │ · 纯Go正则(!cgo)  │  │                  │    │
│   │ sitter │  │                  │  │ 调用图 (caller→   │    │
│   │        │  │ 编译期自动选择     │  │  callee 关系)     │    │
│   │ 5平台  │  │                  │  │                  │    │
│   │ 预编译 │  │ 2.2K 行 Go 代码   │  │ alloc/free 配对   │    │
│   └────────┘  └──────────────────┘  │ 锁图 (mutex 使用) │    │
│                                     │                  │    │
│   支持语言                           │ 60+ 函数/秒      │    │
│   C/C++ · Java · Python             │ 解析速度          │    │
│   Go · JavaScript                   └──────────────────┘    │
│                                                              │
│   💡 为什么自研索引器？                                       │
│   · CodeQL CLI > 500MB，不适合 AI Agent 场景                  │
│   · 我们需要轻量 (< 10MB)、快速 (< 100ms)、跨平台的方案        │
│   · 输出 JSON 直接给 AI 消费，不需要中间格式转换               │
│                                                              │
└──────────────────────────────────────────────────────────────┘

演讲者备注：
- 如果面试官是 infra/系统背景，详细讲双解析器架构和 build tag 设计
- 如果面试官问“为什么不用 clangd/LSP”，回答：太重，且无法提供 alloc/free 配对分析
```

## 附录 A：面试常见问题准备

| 问题 | 答题要点 |
|------|---------|
| "为什么不用 Semgrep/CodeQL？" | 我们是 AI Agent，不是 SAST 工具。互补关系——CodeQL 做规则检测，我们做 AI 深度分析 |
| "误报率多少？" | 诚实回答：未做大规模基准测试。但 AI 语义理解天然比正则规则误报低 |
| "商业模式？" | 面向安全团队的 AI 审计提效工具，手动审计 $20K-50K/次，我们 $2K/年 |
| "为什么用 Go 写索引器？" | 跨平台编译零依赖、tree-sitter 有 Go binding、性能足够 |
| "你的技术深度在哪？" | AI/Renderer 分离架构设计、双解析器编译期选择、四级验证体系 |
| "为什么不做 SaaS？" | 当前阶段验证产品价值，CLI 插件形态更快迭代 |

## 附录 B：PPT 制作建议
