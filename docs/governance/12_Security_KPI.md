# 12 — 安全 KPI 度量 (Security KPI Metrics)

> **对应 Sheet:** `12_Security_KPI`
> **牵引方向:** SecGuardian 安全成效度量体系——量化安全能力成熟度，驱动持续改进。

---

## 1. 概述

安全 KPI (Key Performance Indicator) 是将安全治理从"质"到"量"转化的关键。没有度量就没有改进。本 sheet 涵盖 **4 大 KPI 维度**，每类 10 项指标，共计 **40 项安全 KPI**。

---

## 2. 分类体系

| 维度 | 度量目标 | 严重度分布 | 度量频率 |
|---|---|---|---|
| **Coverage** (覆盖率) | 安全扫描覆盖的数据来源、项目、语言 | 4×Medium, 4×High, 2×Critical | 月度 |
| **Remediation** (修复效率) | 漏洞修复速度和有效性 | 4×Medium, 4×High, 2×Critical | 每周 |
| **Testing** (测试质量) | 安全测试的深度和广度 | 4×Medium, 4×High, 2×Critical | 月度 |
| **Training** (培训成熟度) | 团队安全意识和能力 | 4×Medium, 4×High, 2×Critical | 季度 |

---

## 3. 各维度 KPI 详解

### 3.1 覆盖率指标 (Coverage)

| 编号 | KPI | 计算公式 | 目标值 | 严重度 |
|---|---|---|---|---|
| COV-01 | **项目覆盖率** | 已启用扫描项目数 / 总项目数 × 100% | ≥ 90% | Critical |
| COV-02 | **语言覆盖率** | 已支持的编程语言数 / 团队使用语言数 × 100% | ≥ 80% | High |
| COV-03 | **检测器覆盖率** | 已实现的检测规则 / 应实现的检测规则 | ≥ 80% ASVS L1 | High |
| COV-04 | **CI/CD 集成率** | 已集成安全扫描的 Pipeline / 总 Pipeline | ≥ 95% | Critical |
| COV-05 | **代码行扫描率** | 被扫描的代码行 / 总代码行 | ≥ 90% | Medium |
| COV-06 | **依赖扫描率** | 已扫描依赖项 / 全部依赖项 | ≥ 100% | High |
| COV-07 | **分支覆盖率** | 活跃分支扫描覆盖数 | ≥ 80% | Medium |
| COV-08 | **修复验证率** | 修复后重新扫描并验证的漏洞 / 总修复漏洞 | ≥ 90% | Medium |
| COV-09 | **SBOM 生成率** | 已生成 SBOM 的发布 / 总发布 | ≥ 100% | High |
| COV-10 | **IaC 扫描率** | 已扫描 IaC 仓库 / 总 IaC 仓库 | ≥ 80% | Medium |

### 3.2 修复效率指标 (Remediation)

| 编号 | KPI | 计算公式 | 目标值 | 严重度 |
|---|---|---|---|---|
| REM-01 | **MTTR (平均修复时间)** | 从发现到修复的总时间 / 修复漏洞数 | Critical < 32h / High < 8d | Critical |
| REM-02 | **修复率** | (初始漏洞数 - 当前开放漏洞数) / 初始漏洞数 | ≥ 95% | High |
| REM-03 | **SLA 达成率** | 在 SLA 时间内修复的漏洞数 / 总漏洞数 | ≥ 95% | Critical |
| REM-04 | **漏洞反弹率** | 同一个组件重复出现同类型漏洞的次数 | ≤ 10% | High |
| REM-05 | **平均修复时间趋势** | 本月 MTTR / 上月 MTTR | < 90% (持续下降) | Medium |
| REM-06 | **严重漏洞回归率** | 曾经修复过的类再次出现同类 critical 漏洞 | = 0% | Critical |
| REM-07 | **修复验证失败率** | 修复验证不通过的次数 / 总修复次数 | ≤ 5% | Medium |
| REM-08 | **开放漏洞年龄** | 所有开放漏洞从发现至今的中位数 | ≤ 30 天 | High |
| REM-09 | **积压漏洞数** | 超过 SLA 仍未修复的漏洞总数 | < 10 | High |
| REM-10 | **自动修复占比** | 自动修复的漏洞数 / 总修复漏洞数 | ≥ 30% | Medium |

### 3.3 测试质量指标 (Testing)

| 编号 | KPI | 计算公式 | 目标值 | 严重度 |
|---|---|---|---|---|
| TST-01 | **SAST 误报率** | 误报数 / 总告警数 | ≤ 15% | High |
| TST-02 | **SAST 漏报率** | 遗漏漏洞 / 总应有发现 | ≤ 20% | High |
| TST-03 | **规则精准度** | (Total - FalsePositive - FalseNegative) / Total | ≥ 80% | Critical |
| TST-04 | **安全测试深度** | SAST + SCA + DAST + 渗透测试覆盖 | 至少 2 种扫描类型 | Medium |
| TST-05 | **每次扫描平均检出** | 漏洞数 / 扫描次数 | ≥ 2 (说明发现有效) | Medium |
| TST-06 | **无漏洞项目比例** | 零严重漏洞的项目 / 总项目 | ≥ 80% | High |
| TST-07 | **回归漏洞检出率** | 回归漏洞被自动检测到的比例 | ≥ 90% | Medium |
| TST-08 | **严重漏洞密度** | 严重漏洞数 / 代码行数 (每 10 万行) | < 5 | High |
| TST-09 | **测试覆盖率** | 安全测试覆盖的攻击面 / 总攻击面 | ≥ 70% | Medium |
| TST-10 | **威胁模型评审率** | 完成威胁建模的新增功能 / 总新增功能 | ≥ 80% | High |

### 3.4 培训成熟度指标 (Training)

| 编号 | KPI | 计算公式 | 目标值 | 严重度 |
|---|---|---|---|---|
| TRN-01 | **安全培训完成率** | 完成培训的开发人员 / 开发人员总数 | ≥ 95% | High |
| TRN-02 | **培训考试成绩平均分** | 安全测验平均分 | ≥ 80 分 | Medium |
| TRN-03 | **安全意识评测** | 年度安全知识评估 | ≥ 90% 通过 | Medium |
| TRN-04 | **安全 champions 比例** | 安全 champions / 总开发人员 | ≥ 10% | High |
| TRN-05 | **漏洞根因学习案例** | 每次严重漏洞修复后产出的学习案例 | = 100% | Critical |
| TRN-06 | **培训更新频率** | 安全培训内容的更新时间间隔 | ≤ 6 个月 | Medium |
| TRN-07 | **新员工安全培训** | 新员工入职 30 天内完成安全培训 | = 100% | High |
| TRN-08 | **安全认证持有率** | 持有安全认证 (CISSP/CSSLP) 的团队成员 | ≥ 5% | Medium |
| TRN-09 | **安全周/月活动** | 年度安全活动次数 | ≥ 2 次/年 | Medium |
| TRN-10 | **安全工具使用培训** | 使用 SecGuardian 的团队培训覆盖率 | ≥ 90% | High |

## 4. 业界对标

### 4.1 安全成熟度模型

| 成熟度 | 描述 | KPI 达标比例 | 典型企业 |
|---|---|---|---|
| **Level 1 - 起始** | 安全活动零散，依赖个人英雄 | < 30% | 初创 |
| **Level 2 - 定义** | 安全流程有定义但执行不统一 | 30%-50% | 成长期 |
| **Level 3 - 管理** | 安全流程标准化，可度量 | 50%-75% | 中型企业 |
| **Level 4 - 量化** | 用数据驱动安全决策 | 75%-90% | 大型企业 |
| **Level 5 - 优化** | 安全持续优化，自动化成熟 | > 90% | 行业标杆 |

**SecGuardian 目标：4 级以上。**

### 4.2 行业安全度量框架

- **[BSIMM](https://www.synopsys.com/software-integrity/software-security-services/bsimm.html)** (Building Security In Maturity Model) — 12 个实践域，113 项活动
- **[OWASP SAMM](https://owaspsamm.org/)** (Software Assurance Maturity Model) — 5 个业务功能，15 个安全实践
- **[NIST CSF](https://www.nist.gov/cyberframework)** (Cybersecurity Framework) — 5 个核心功能

### 4.3 BSIMM-DSS 对标参考

| BSIMM 活动 | SecGuardian KPI 映射 |
|---|---|
| SM 1.1 — 识别安全带头人 | TRN-04 (安全 champions) |
| SE 1.1 — 统一安全规范 | COV-01 ~ COV-04 (覆盖率 KPI) |
| SR 1.1 — 确定安全需求 | TST-10 (威胁建模率) |
| SR 2.4 — 漏洞追踪 | REM-01 ~ REM-10 (修复 KPI) |
| ST 1.1 — 安全培训 | TRN-01 ~ TRN-10 (培训 KPI) |

## 5. SecGuardian 牵引方向

### 5.1 自动化数据采集

KPI 不应依赖人工填写。SecGuardian 应自动采集以下数据源：

| 数据源 | 采集方式 | 关联 KPI |
|---|---|---|
| SAST 扫描结果 | 自动 | COV, TST |
| SCA 扫描结果 | 自动 | COV, REM |
| Git 仓库元数据 | API | COV-01, COV-07 |
| CI/CD Pipeline 日志 | API | COV-04 |
| 漏洞跟踪系统 (Jira) | API | REM-01 ~ REM-10 |
| 培训系统 | API | TRN-01 ~ TRN-10 |

### 5.2 仪表盘设计

```
SecGuardian KPI Dashboard (示例)
   ┌─────────────────────────────────────────────────┐
   │  安全态势 | 本月     | 目标    | 趋势    │
   ├─────────────────────────────────────────────────┤
   │  🟢 项目覆盖率       92%   | ≥ 90%  | ↑ 5%  │
   │  🔴 SLA 达成率       78%   | ≥ 95%  | ↓ 3%  │
   │  🟡 严重漏洞密度     3.2   | < 5    | → 0%  │
   │  🟢 培训完成率       97%   | ≥ 95%  | ↑ 2%  │
   │  🔴 漏洞反弹率       15%   | ≤ 10%  | ↑ 5%  │
   └─────────────────────────────────────────────────┘
```

### 5.3 发展路线

| 阶段 | 目标 |
|---|---|
| **Phase 1** | 覆盖率 + 修复效率计板 (自动) |
| **Phase 2** | 测试质量指标 + 趋势分析 |
| **Phase 3** | 培训成熟度集成 + 自动报表 |
| **Phase 4** | 安全成熟度评级 + 改进建议 (AI 驱动) |

### 5.4 与现有能力融合

```
各 skill 检测数据
   │
   ▼
数据汇聚层 (自动采集)
   │
   ├─ 覆盖率 → COV-01 ~ COV-10
   ├─ 修复率 → REM-01 ~ REM-10
   ├─ 质量   → TST-01 ~ TST-10
   └─ 培训   → TRN-01 ~ TRN-10
   │
   ▼
KPI Dashboard + 报表
   │
   ▼
管理决策 (资源分配 / 风险接受 / 改进方向)
```
