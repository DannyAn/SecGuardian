# 双重释放跨函数追踪

## 规则

同指针在多个函数中被释放时，通过调用图确认是否存在可达路径触发两次释放。

### 最大深度: 1 层

当 free(p) 在函数 A 和函数 B 中、且 A 调用 B 时：
```c
void A() {
    free(p);       // 第一次释放
    B();           // 调用 B
}

void B() {
    free(p);       // 第二次释放，如果 p 未重新赋值
}
```

### 深度超过 1 层 → 降级为 suspicious

```c
void A() { free(p); }
void B() { A(); }  // depth 2
void C() { B(); }  // depth 3
```
只要调用图可确认 C→B→A 的调用路径，且 p 在链上未重新赋值，仍报告但降级严重度。

## 常见模式

1. **初始化失败 + 析构**：`init()` 中部分分配失败时释放已分配资源，然后 `~destructor()` 尝试再次释放 → 需在 init 失败路径上将指针置 NULL
2. **引用传递释放**：函数接受指针参数并可能释放，调用点后调用者又释放同一指针 → 需检查函数命名约定中是否隐含所有权转移语义
