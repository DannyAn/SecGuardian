# C/C++ 安全反模式

代码审查中需要关注的 C/C++ 特有安全反模式。

## 内存管理反模式

| 反模式 | 风险 | 正确做法 |
|--------|------|---------|
| `new`/`delete` 与 `malloc`/`free` 混用 | 未定义行为 | 保持配对一致 |
| `delete` 数组用 `delete` 非 `delete[]` | 未定义行为 | `new[]` → `delete[]` |
| 异常路径未释放资源 | 内存泄露 | RAII / scope guard |
| 裸指针管理所有权 | 双重释放 / UAF | `std::unique_ptr` / `std::shared_ptr` |

## 类型安全反模式

| 反模式 | 风险 | 正确做法 |
|--------|------|---------|
| C 风格 cast `(Type)val` | 绕过类型检查 | `static_cast` 等 C++ cast |
| `reinterpret_cast` 非必要使用 | 类型安全完全绕过 | 重构设计避免需要 |
| `const_cast` 修改 const 对象 | 未定义行为 | 设计时避免 |

## 并发反模式

| 反模式 | 风险 | 正确做法 |
|--------|------|---------|
| `volatile` 用作同步 | 不保证原子性或顺序 | `std::atomic` |
| 无锁数据结构手写 | 极难正确实现 | 使用标准库或成熟库 |
| 析构函数中访问已销毁的静态对象 | 静态析构顺序问题 | 避免静态对象互相依赖 |

## 未定义行为

| 反模式 | 风险 |
|--------|------|
| 有符号整数溢出 | 未定义行为，编译器可能删除安全检查 |
| 空指针解引用 | 未定义行为 |
| 越界访问 (OOB) | 缓冲区溢出 |
| 使用已释放内存 (UAF) | Use-After-Free |
| 重叠内存 `memcpy` (应使用 `memmove`) | 未定义行为 |
