# Data Flow Analysis — 数据流分析参考

> 追踪敏感数据在系统中的完整生命周期：采集 → 处理 → 存储 → 传输 → 展示 → 销毁。

## 何时使用

适用于追踪敏感数据流的审计域：
- Data Protection — 追踪 PII/敏感数据流经的系统组件
- Secrets Management — 追踪密钥/凭证的读取和传递路径
- Cryptography — 追踪加密/解密操作的数据流
- Logging & Monitoring — 追踪敏感数据是否进入日志流

## 关键节点

### 采集点（Data Collection）
数据进入系统的位置：
- 用户注册/登录表单
- API 请求体（包含 PII）
- 文件上传（包含敏感内容）
- 第三方数据同步

### 处理点（Processing）
数据被变换的位置：
- 数据脱敏/匿名化
- 加密/解密操作
- 数据聚合/分析
- 格式转换（JSON/XML/CSV）

### 存储点（Storage）
数据持久化的位置：
- 数据库：关系型 SQL、NoSQL
- 缓存：Redis、Memcached
- 文件系统：日志文件、导出文件
- 对象存储：S3、OSS

### 传输点（Transmission）
数据跨服务流动的位置：
- 内部 RPC 调用
- 消息队列发送
- API 外部调用
- 日志/监控系统推送

### 展示点（Presentation）
数据对外呈现的位置：
- HTTP 响应体
- 管理后台页面
- 导出报表
- 日志输出

## 异常流向检测

以下情况应标记为风险：
1. **数据进入不应去的系统组件** — 如 PII 进入日志系统
2. **数据未经脱敏就展示** — 如管理后台显示完整身份证号
3. **数据存储未加密** — 如 PII 以明文写入数据库
4. **数据跨信任边界未控制** — 如内部数据被 API 返回给外部用户

## 执行步骤

1. 识别审计域相关的敏感数据类型
2. 追踪该类型数据的所有采集、处理、存储、传输、展示节点
3. 构建数据流图（采集 → ... → 展示/销毁）
4. 检查每个节点是否有对应的安全控制（加密、脱敏、访问控制）
5. 标记缺少安全控制的节点为风险
