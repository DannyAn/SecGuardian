# Attack Surface Analysis — 攻击面分析参考

> 识别和枚举系统的所有外部入口点、暴露接口和攻击向量。

## 何时使用

适用于需要评估暴露面的审计域：
- Infrastructure Hardening — 识别暴露的服务、端口、端点
- Dependency Security — 评估第三方组件引入的攻击面
- HTTP Security Headers — 评估 HTTP 暴露面的安全配置
- Authentication — 识别所有认证入口点

## 入口点分类

### Web 入口
- HTTP/HTTPS 端点（路由定义、中间件）
- WebSocket 端点
- GraphQL 入口
- gRPC 服务定义
- REST API 路由

### 消息入口
- 消息队列消费者（Kafka、RabbitMQ、SQS）
- 事件总线订阅者
- Webhook 回调端点

### 文件入口
- 文件上传端点
- 文件导入处理
- 配置文件读取

### 进程入口
- CLI 命令和参数
- 定时任务/Cron 触发器
- 后台 worker/daemon 接口
- 信号处理

### 网络入口
- 监听端口
- RPC 服务
- UDP/TCP 服务
- Unix Socket

## 暴露面评估

对每个入口点评估：

| 维度 | 问题 |
|------|------|
| 认证 | 是否需要认证？认证机制是什么？ |
| 授权 | 是否有访问控制？权限模型是什么？ |
| 输入验证 | 输入是否经过验证和净化？ |
| 限流 | 是否有速率限制防止滥用？ |
| 日志 | 是否记录访问日志？ |
| 监控 | 是否有异常检测和告警？ |

## 执行步骤

1. 识别项目架构中的所有外部入口点
2. 对每个入口点，评估其暴露级别（公网/内网/本地）
3. 检查入口点是否有安全控制（认证/授权/验证）
4. 枚举每个入口点支持的协议、数据格式、操作
5. 构建攻击面地图（入口点 → 后端流程 → 数据流）
6. 标记缺少安全控制的入口点为风险
