# State Machine Analysis — 状态机分析参考

> 分析系统各个组件的状态转换，检测非法状态跃迁、不一致的状态和竞争条件。

## 何时使用

适用于涉及状态转换的审计域：
- Authentication — 认证状态机（未认证 → 已认证 → 会话过期）
- Authorization — 权限状态转换
- Business Logic — 业务状态机（订单状态、工作流状态）
- Cryptography — 协议状态机（TLS handshake）
- Data Protection — 数据生命周期状态

## 典型状态机

### 认证状态机
```
未认证 → 登录成功 → 已认证 → 会话过期 → 未认证
                        ↓
                   登录失败 → 已锁定 → 解锁 → 未认证
```
风险：从"未认证"跃迁到"已认证"不需要密码、会话固定攻击

### 业务状态机（订单）
```
待支付 → 已支付 → 已发货 → 已完成
   ↘         ↘        ↘
   已取消    已退款    已退货
```
风险：从"已发货"跃迁到"待支付"（状态回退）、重复支付

### 密码重置状态机
```
请求重置 → Token 已发送 → Token 验证 → 密码已重置
```
风险：Token 可被预测、Token 不绑定用户、无有效期

## 状态跃迁检测

### 非法跃迁
检查是否可以从状态 A 直接到达状态 C 而跳过 B：
- 例如：从"未认证"直接到"已认证"绕过登录
- 例如：从"待支付"直接到"已完成"绕过支付

### 状态回退
检查是否可以从"已完成"状态的实体回退到"处理中"：
- 例如：已付款订单回退到待付款
- 例如：已完成审核的文档回退到待审核

### 并发状态
检查是否存在两个互斥状态同时为真的情况：
- 例如：同一订单同时为"已支付"和"已取消"

## 执行步骤

1. 识别审计域涉及的状态机
2. 枚举所有合法状态和状态转换
3. 检查代码中状态转换的实现方式
4. 检测非法跃迁路径（跳过中间状态）
5. 检测状态回退漏洞
6. 检查并发状态冲突
